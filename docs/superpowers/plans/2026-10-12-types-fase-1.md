# Types Fase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A desktop app where Diego writes Markdown pages inside per-business spaces and chats with his installed Claude Code, which reads and writes those same files while the app refreshes live.

**Architecture:** Tauri 2 shell. Rust owns the filesystem (validated paths under one workspace root), a file watcher, and a runner that spawns the Claude Code CLI per message and relays its stream-json output as events. React renders a three-pane layout (sidebar, document, chat) and talks to Rust only through `src/lib/api.ts`.

**Tech Stack:** Tauri 2, Rust (notify, trash, serde, dirs), React 19, TypeScript, Vite, pnpm, Zustand, Tiptap + Markdown, Vitest.

**Spec:** `CLAUDE.md` (repo root). Read it fully before any task.

## Global Constraints

- Model rule: code is written by Sonnet subagents; they read `CLAUDE.md` first and stop on conflict.
- Confirm every library API with context7 before using it.
- Workspace root defaults to `~/Documents/TYPES-espacios`; never inside this repo.
- Pages are plain GFM Markdown. No proprietary format, no database.
- No command accepts a path that resolves outside the workspace root.
- Deleting moves to the system trash.
- Autosave debounce: 800 ms. Opening a file never writes it.
- UI copy in Spanish; code, identifiers and commits in English.
- Work on branch `feat/fase-1`; never commit to `main` directly after the initial commit.
- Node via nvm (`source ~/.nvm/nvm.sh`), Rust via `~/.cargo/bin`. No Xcode, no brew installs.
- Embedded Claude flags exactly as in `CLAUDE.md` §4; no Bash tool.

## Review Focus

1. A path such as `../x`, `/etc/hosts`, or a symlink pointing outside the root is rejected by every command (Task 2 tests).
2. A file changes on disk while Diego has unsaved edits: his text is kept and he is asked, never silently overwritten (Task 5 tests).
3. Opening and closing a Claude-written page with tables and images leaves the file byte-identical (Task 5 tests).
4. Claude binary missing or not logged in: the chat shows a clear Spanish message with what to do, the app does not hang (Task 3 and 7 tests).
5. Names with spaces, accents and `ñ` (`Diseño otoño.md`) work in tree, open, rename and attachments (Task 2 tests).

### Task 2: Workspace core (Rust)

**Files:** Create `src-tauri/src/{error.rs,settings.rs,workspace.rs,templates.rs}`; modify `lib.rs`, `Cargo.toml`.

**Interfaces (Produces):**
```rust
pub struct Settings { pub workspace_root: PathBuf, pub claude_path: Option<PathBuf> }
pub fn resolve(root: &Path, rel: &str) -> Result<PathBuf>   // rejects escapes
#[derive(Serialize)] pub struct TreeNode { name: String, path: String /* relative, '/' separated */, kind: NodeKind /* "dir" | "file" */, children: Vec<TreeNode> }
```
Tauri commands (all paths relative to workspace root):
`get_settings() -> Settings` · `set_workspace_root(path: String) -> Settings` · `set_claude_path(path: Option<String>) -> Settings` · `list_tree() -> Vec<TreeNode>` · `read_text(path) -> String` · `write_text(path, content)` · `create_space(name) -> String` · `create_page(dir, name) -> String` (appends `.md`) · `create_folder(dir, name) -> String` · `rename_entry(path, new_name) -> String` · `delete_entry(path)` · `import_files(dest_dir, sources: Vec<String>) -> Vec<String>` · `save_attachment(space, file_name, bytes: Vec<u8>) -> String`.

Rules: settings JSON in the app config dir; first run creates the workspace root with the root `CLAUDE.md` template; `create_space` creates `<name>/CLAUDE.md` from the space template and `<name>/adjuntos/`. Tree is sorted dirs first then name (case-insensitive), skips dot-entries. Name collisions get a ` 2`, ` 3` suffix. Names are rejected if empty or containing `/`, `\`, or starting with `.`. `delete_entry` uses the `trash` crate. `save_attachment`/`import_files` write into `<space>/adjuntos/`.

Templates (Spanish) must state: pages are GFM Markdown with descriptive text plus tables for hard data; visual outputs are self-contained HTML; attachments live in `adjuntos/`; show formulas and assumptions in every calculation; never delete or rewrite Diego's text without being asked. The space template has headed blanks: Qué es este negocio, Proveedores y tarifas, Mermas y supuestos, Márgenes objetivo, Cómo quiero los reportes.

### Task 3: Watcher and Claude runner (Rust)

**Files:** Create `src-tauri/src/{watcher.rs,claude.rs}`; modify `lib.rs`, `Cargo.toml`, `capabilities/`.

**Interfaces:**
- Consumes: `Settings`, `resolve`.
- Produces event `fs-changed` payload `{ paths: string[] }` (relative, debounced 150 ms, dot-entries ignored). Watcher restarts when the workspace root changes.
- Produces commands `claude_status() -> { found: bool, path: Option<String>, version: Option<String> }` · `claude_send(space: String, text: String, attachments: Vec<String>, session_id: Option<String>) -> u32 /* run id */` · `claude_stop(run_id: u32)`.
- Produces event `claude-event` payload `{ run_id: u32, kind: "raw", line: serde_json::Value }` for each stdout JSON line, `{ run_id, kind: "stderr", text }`, and a final `{ run_id, kind: "exit", code: Option<i32> }`.

```rust
pub fn find_claude(settings: &Settings, home: &Path, path_lookup: impl Fn() -> Option<PathBuf>) -> Option<PathBuf>
pub fn newest_vscode_binary(extensions_dir: &Path) -> Option<PathBuf>   // semver compare on anthropic.claude-code-<ver>-*
pub fn build_args(text: &str, attachments: &[String], session_id: Option<&str>) -> Vec<String>
```
`build_args` returns exactly the flags in `CLAUDE.md` §4. With attachments, the prompt is the text followed by a blank line and `Archivos adjuntos (léelos con Read):` plus one `- <relative path>` line each. `path_lookup` in production runs `zsh -lc 'command -v claude'`. The child runs with `cwd` = resolved space dir, stdin closed. Non-JSON stdout lines are forwarded as `stderr` kind.
